# goal

Autonomous pursuit of one user objective per session: windowed token accounting, a hard core budget, 3-turn blocked-audit discipline, durable continuations, and declarative views — all through the public SDK.

## Surface

- Tool `get_goal` (`READ`, safe): current goal state, budgets, token/elapsed usage, remaining budget.
- Tool `create_goal` (`SESSION`, never replayed): create a goal; refused while an unfinished goal exists. Objective must be non-empty and at most 4000 chars through the tool.
- Tool `update_goal` (`SESSION`, never replayed): mark the goal `complete`, or propose `blocked` (accepted only on the third distinct logical turn; attempts 1–2 fail while staging the count). Pause/resume/limited transitions are user/system-controlled, not model tools.
- Commands (all `busy_gate=False`): `/goal` (`READ`: inspect state and remaining budget), `/goal set` (`WRITE` + `SESSION`: create or replace; unfinished replacement returns `pending_confirmation`, an accepted confirm executes it once), `/goal edit` (`WRITE` + `SESSION`: edit objective or budget; a finite raise needs known closed-window spend, `token_budget=null` uncaps), `/goal pause` (`SESSION`: valid from active/blocked/usage-limited/budget-limited), `/goal resume` (`SESSION`: re-open a window and re-arm), `/goal clear` (`SESSION`: direct clear, no extra confirmation), `/goal load_objective` (`READ`: return the full objective text exactly once in `data.objective`).
- Views: `goal` (status banner: status, truncated preview, token count), `goal.details` (fields: status, objective, budget, tokens used, elapsed), `goal.form` (create form when empty, edit form otherwise — preserving identity, creation time, usage, and budget).
- Context: the active goal contributes its prompt in the legacy user role every dispatch; the observer (`usage`, `invocation_finished`, `run_finished`) attributes spend and stages budgets/continuations.

## Configuration

Takes no plugin config; `create_plugin` accepts and ignores its mapping. See [configuration](../../../../docs/configuration.md) for global config.

## Behavior and limits

- State (`GoalState`, `schema_version 1`, session scope, strict parsing — unknown keys rejected, required fields enforced, unreported metrics stay `None` never `0`): identity, status (`active | paused | blocked | usage-limited | budget-limited | complete`), objective (inline or spilled), lifetime + window token/cost/time counters, contiguous dispatch-sequence accounting windows, blocked-turn count, and the objective-edited bit.
- Windowed accounting: an active window opens on create/resume (`start_sequence = tip`) and closes on pause/complete/block at the actual stop sequence; dispatches before creation or during a pause are excluded, while in-flight dispatches arriving after a pause still attribute to their dispatch window. Enforcement is window-scoped (`window_tokens_used` vs `window_allowance`): reaching the allowance means `budget-limited`, unreported window spend means `usage-limited`. In both cases the plugin cancels its own queue and retains the core constraint — it never uncaps an in-flight user budget. An explicit budget edit keeps the live window and re-stages `new_budget − closed-window spend`; unknown closed-window spend refuses a finite raise or budgeted resume visibly (uncap or start a new goal — no allowance is invented). Late bills for a closed window tighten the live allowance while active, or update lifetime counters only while paused. Unbudgeted resume clears any stale constraint.
- Unknown spend is never zero: one unreported dispatch sets every token total to `None` (still accounting reported elapsed/cost), unknown stays unknown across later reports, and unknown cost never poisons known tokens. Elapsed time accumulates measured `elapsed_seconds`; `RunFinishedFact` neither fabricates `0` nor double-counts.
- Objectives over 4000 chars spill immutably to `.voidcode/attachments/<uuid>/goal-objective.md` (exclusive create, workspace containment, SHA256 integrity; missing/modified files error visibly; never deleted on replace/clear). The full objective crosses the wire exactly once via `goal.load_objective`; the edit form prefills inline objectives but uses `load_action` for spilled ones. No goal-specific size cap: the platform bounds still apply (notably the 64 KiB view-data limit) and fail visibly instead of truncating.
- Blocked discipline: counted at most once per distinct logical turn; reset by any successful non-goal tool call, a clean completed turn with no blocked attempt in it, `goal.resume`, or an objective edit.
- Prompt parity: the active/budget/edited prompts are the legacy goal texts (persistence, no-shrinking, evidence-first, explicit `update_goal status="complete"`, four-point blocked audit), delivered as a user-role contribution; the objective-edited notice is retained until replace/clear, so it repeats in later contexts rather than risk being swallowed by an in-flight dispatch. Nullable counters render as `unknown`, absent budget as `none`, unbounded as `unbounded`.
- Disabling (via `core.reload`) runs the pure deactivation transform: every open window closes at the owning session's event tip, live statuses become `paused` (`complete` stays), and identity/objective/counters/budget survive unchanged; the paused goal contributes no context and nothing re-arms until an explicit `goal.resume`. Malformed scope/tip/payload refuses visibly instead of resetting.
