# files

Workspace file read, write, edit, and search tools.

This package is a thin adapter: the shared `voidcode.capabilities.files` handlers decorate their public `invoke` boundary so expected diagnostics and argument-validation errors surface as typed model-visible failures. `create_plugin` registers those decorated tools directly; no plugin-owned wrapper is involved.

## Surface

- Tool `read` (`READ`): read a file or resource URI. An untruncated page that starts at `offset=1` and reaches EOF returns a SHA-256 `content_hash`, one whole-file read observation, and the line count. A page starting at `offset>1` never returns a whole-file hash or coverage, even when it reaches EOF. A partial page (more lines remain) returns no hash and no coverage and keeps `next_offset`. Line count is reported whenever the read reaches EOF, including `offset>1` pages and clipped-page artifact passes that scan to EOF. `read(hash_only=true)` streams a regular file path with bounded memory and returns only its `sha256` and byte size — the explicit way to obtain `expectedHash` after a partial read. It is mutually exclusive with `offset`/`limit`/`byte_offset`/`byte_limit` and with resource URIs. A path containing `://` is always a resource URI; there is no filesystem fallback.
- Resource readers `tool://`, `artifact://`, `transcript://`: the default namespaces this plugin serves (tool docs, stored-artifact pages, lineage-gated transcript pages). Each parses its own URI and default, and declares which generic cursors it honors: `artifact://` pages lines with a 1-based `offset` and bytes with `byte_offset`/`byte_limit` (its body's `offset_unit` says which); `transcript://` pages with the URI's own UTF-8 byte cursor and rejects `offset`; `tool://` is one document and rejects `offset != 1` and `limit`. Resource failures are typed: malformed arguments as `tool_input_mismatch`, lineage denial as `resource_access_denied`, backend failures as `tool_environment_error`, and an unknown name/id as `target_not_found`.
- Tool `write` (`WRITE`, never replayed): write a UTF-8 text file inside the workspace. It commits the caller's text verbatim, including its line endings, so it can create a mixed-ending file; `edit` refuses mixed-ending inputs instead of normalizing them. Creating a file needs no hash and is exclusive (`os.link`, never a check-then-replace). Overwriting needs `expectedHash`; the previous version is re-checked by streamed hash at the commit boundary. A previous file of at most 64 KiB also yields a diff; larger files report only the new hash. Every failure is a typed `ToolFailure` with a diagnostic kind, reason, and retry guidance.
- Tool `edit` (`WRITE`): two modes sharing one mutation core. Text mode replaces exact current text (single replacement or ordered batch) and checks only `expectedHash`; it never consults a document-state provider. Range mode (`mode="range"`) is the freshness-aware path: it applies 1-based line/character edits across one or more files, asks any active document-state provider, and refuses a provider hash or requested `version` that no longer matches. `positionEncoding` may be `utf-8`, `utf-16`, or `utf-32`. Every edit carries `expectedHash`; `version` optionally binds it to the provider's version answer. Text matching is EOL-insensitive: content and `oldString` are normalized to LF for matching and committed bytes use the file's one uniform ending (LF, CRLF, or lone CR). A mixed-ending file is refused with a diagnostic, never silently normalized. Success output names the new SHA-256 of every changed file, and each `Change` carries it as `content_hash`.
- Tool `glob` (`READ`): find files matching a glob pattern, newest modified first (ties by path), with the limit applied after ordering.
- Tool `grep` (`READ`): search workspace files; literal by default, `regex=true` for regular expressions. Files that are not UTF-8 text are skipped and counted in `skipped_undecodable`, never silently ignored.
- Queries `workspace.find_grep` and `workspace.find_read`: typed, bounded read-only access for the `find` plugin. The handlers invoke the same `GrepTool`/`ReadTool` implementations exposed to the model, preserving path validation, truncation, diagnostics, and page bodies. Disabling this plugin removes the queries, so `find` fails visibly instead of reading the workspace itself; malformed query answers are contract errors.
- Query `workspace.path_completion`: typed, workspace-relative `@path` candidates for clients. The request carries one draft prefix (never a server absolute path), `prefix` or ordered-subsequence `fuzzy` matching, a depth of 1–16 directory levels, a result limit of 1–200, hidden-entry opt-in, and optional root `.gitignore` filtering. Prefix matching tests the entry name; fuzzy matching tests the path below the requested directory, which is what makes recursive fuzzy searches select nested files. The answer echoes the exact request query and returns only bounded workspace-relative paths; directories end with `/`. Default ignored names (`.git`, `node_modules`, `__pycache__`, `build`, ...), hidden components unless explicitly typed, and symlinks resolving outside the workspace are never offered, so a candidate can never lead a client outside the server workspace. Ordering is deterministic (directories first, then casefolded path; fuzzy matches rank by first match, gaps, and length). Disabling this plugin makes the query unavailable, and the TUI reports that instead of reading its own local file system.
- `glob` and `grep` share one default discovery policy and one glob dialect: hidden entries are included and `.gitignore` is not applied unless asked; `include`/`exclude` use the same `pathlib` `full_match` semantics as `glob`'s pattern, so `*.py` matches at any depth. `find` deliberately defaults to gitignore-respecting behavior-search instead.

## Configuration

Takes no plugin config; `create_plugin` ignores it. See [configuration](../../../../docs/configuration.md) for global config.

## Behavior and limits

- Path policy: `write` and both `edit` modes refuse any resolved target outside the workspace with a typed `ToolFailure`; a path the filesystem cannot resolve (such as one with an embedded NUL) is reported as `invalid_path`, not as an external target. A literal leaf that is a symlink is refused (`symlink_target`) rather than silently rewriting the link's target. `read`, `glob`, and `grep` keep external read access; `WRITE` approvals and read-only stance are the gates that apply to mutations.
- One mutation-content bound: a single `write`, text `edit`, or range `edit` call may supply at most 64 KiB of replacement text (`content`, the sum of `newString`, or the sum of `newText`, measured in UTF-8 bytes). The bound is on the caller's payload, not on the resulting file size, so a large file stays editable across several calls. The same typed `input_too_large` failure is used by all three.
- File mutations validate explicit caller evidence and exact matching — replacement modes compare caller-supplied content hashes, and no mode requires a prior session read. Read observations are historical facts, not write permissions (see [facts](../../../../docs/contracts/facts.md)). Stale-hash, ambiguous-match, mixed-line-ending, expected-hash-required, and commit-race failures surface as typed `ToolFailure` results with retry guidance; a commit race is reported as `stale_edit`/`commit_race` and tells the caller to re-read.
- `read` stops making page decisions after the requested page plus a cheap one-byte EOF probe. It may read ahead up to one 8 KiB raw chunk, but it never decodes unseen later bytes. It never materializes an unbounded line: a visible line beyond 2000 characters switches to the full-file pass, renders a truncated prefix, and does not claim a whole-file hash. The artifact used for byte paging is spilled only when a clipped line is actually returned, and its digest and byte count must match the pass that rendered the page; an overlong line that never reaches the page leaves no stored artifact behind. The rendered content page reserves the `TextOutput` envelope (`MAX_RESOURCE_PAGE_BYTES`) so a near-budget whole-file read is not projection-clipped.
- `TextOutput.text` is the selected page. Its typed body retains machine fields such as `raw_content`, line records, and the whole-file hash at the canonical result artifact when Core omits that redundant body; omission alone does not mark the page or `ReadObservation` clipped.
- Raster reads publish original bytes through streaming artifact ingress rather than an arbitrary media-size cutoff. Real Core/native Anthropic and Google routes preserve valid decoded PNG pixels above the 256 KiB artifact-page size; complete bytes remain pageable by digest. Binary sniffing treats ESC as text so ANSI-coloured logs are rendered as text.
- Multi-file range commits preflight every path, hash, document version, and range before the first write. A later I/O failure may leave an applied prefix; the failure reports that prefix, its changes (with each file's hash), and the uncommitted remainder.
- Query-absence behavior: `read`/`write`/text `edit` never consult a workspace query; range `edit` with `version` fails closed (`document_version_unavailable`) when no provider answers, while edits carrying only a content hash (no version) work without any provider. A provider hash or version mismatch is a typed stale failure; a malformed answer is a visible contract failure. The `find` queries disappear with this plugin; a disabled files plugin therefore yields a typed `find_files_unavailable` failure in find, never a direct-read fallback.
- `read` is the only dispatcher for resource URIs. Disabling this plugin therefore removes every registered scheme (`skill://`, `web://`, `agent://`, `proc://`) from model reach even though their plugins still register readers; it is an admission-time coupling, not a fallback. `tests/unit/core/test_resource_readers.py` pins it.
- Write-class tools declare `WRITE` and route through the core's approval check; see [plugin authoring](../../../../docs/contracts/plugin-authoring.md) for the surrounding contract.
