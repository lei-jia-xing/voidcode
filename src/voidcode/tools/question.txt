Ask the user clarifying questions and wait for an answer.

Usage:
- Use this tool when you need a structured user decision before continuing.
- Provide a non-empty `questions` array.
- Each question must include `question` and `header`, with optional `options`, `multiple`, and `allow_freeform`.
- `header` must be unique and should be short/stable because the runtime uses it to match answers.
- Each option needs a non-empty, unique `label`; `description` is optional.
- Options may be empty only when `allow_freeform=true`; then answers need not match declared labels.

Important:
- This tool pauses the current session until the user answers or cancels.
- Do not call this for information you can determine from the repo or existing context.
- Keep options concise and mutually distinct.
- Use `multiple=true` only when more than one answer is genuinely allowed.
- Duplicate question headers are rejected before the session pauses.

Answer format:
- Answer every header exactly once with one or more non-empty, unique answers.
- Single-choice questions accept exactly one answer; multiple-choice questions accept multiple answers.
- Unless `allow_freeform=true`, each answer must exactly match a declared option label.
- Cancellation is an explicit response and is persisted as such; it is not a blank answer.

Example shape:
- One question with single choice: header `Runtime path`, options `Reuse existing` and `Add new path`.
- One question with multiple choice: header `Checks`, options `Tests`, `Typecheck`, `Build`, and `multiple=true`.
- One freeform question: header `Details`, `options=[]`, and `allow_freeform=true`.
