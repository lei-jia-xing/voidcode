Performs targeted changes to files via single text replacement, ordered batch replacements, or patch application.

Usage:
- Three mutually exclusive modes are supported:
  1. Single replacement: provide `path`, `oldString`, `newString`, and `expectedHash` (optional `replaceAll: true`).
  2. Ordered replacements batch: provide `path`, `edits` (array of `{oldString, newString, replaceAll}`), and `expectedHash`.
  3. Patch: provide `patch` (unified diff or structured `*** Begin Patch` / `*** End Patch` envelope) and optional `expectedHashes` (map of path -> SHA-256 hash for existing files modified/deleted).
- Read target files first: `expectedHash` (or `expectedHashes`) is taken from the read output's SHA-256 content hash. Edits without expected hashes or with stale hashes are rejected before writing.
- The `path` parameter may be workspace-relative or absolute; runtime approval governs filesystem access.
- For replacements (`oldString`/`newString` or `edits`), `oldString` must match existing file content. Omit line-number prefixes shown in read output (such as `42: `).
- Batch edits are validated and preflighted entirely in memory before writing to disk; if any edit in the batch fails, no files are modified.
- Use `write` when creating new files or intentionally replacing a complete file.
